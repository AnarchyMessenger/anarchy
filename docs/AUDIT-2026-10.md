# Audit, October 2026

A pass over the server, the core, the desktop bridge and the desktop UI for security holes and likely bugs, plus the design rules from the `design-taste-frontend` skill that apply to an app (that skill targets landing pages; its layout rules for heroes, bento grids and marketing copy don't apply here).

## Fixed

| What | Why it mattered | Fix |
|---|---|---|
| Inline `style` attributes were refused by the app's CSP (`style-src 'self'`). | In the real app (not the preview, which had no CSP) the sidekick maker's faces all collapsed onto the centre and couldn't be clicked, colour swatches had no colour, and every staggered animation lost its delay. | The element helpers in `app.js` and `sidekick.js` set styles through the CSSOM (`style.cssText`), which the CSP allows. |
| The preview didn't run under the app's CSP. | That's how the bug above went unseen. | `ui-preview.mjs` serves the UI over HTTP with the CSP from `tauri.conf.json` and reports each refusal with file and line; any refusal fails the run. |
| `busy()` and `copy()` restored a button by re-parsing its saved `innerHTML`. | Re-parsing drops event listeners on the button's children and re-applies inline styles the CSP refuses. | They keep and restore the original nodes. |
| The sidekick maker in Settings → Profile was squeezed into a 290-pixel column, with its side panel over the stage. | Unusable there since it shipped. | A container query stacks the panel under the stage whenever the maker is narrow; in Settings the page widens while the maker is open. |
| The mention picker closed itself about 120 ms after you moved from one text box to another. | The old box's delayed close fired after the new box had opened the picker. | The delayed close checks focus first (`closeMentionSoon`). |
| A device could store any number of its own key packages. | Unbounded storage per device. | The server keeps the newest 200 per device and drops older ones; uploads never fail for it, so sign-in can't break. |
| The email lookup limit answered 403. | Clients couldn't tell "not allowed" from "slow down". | It answers 429, like the other limits. |
| Em and en dashes in visible text (time ranges, empty money cells). | House style for visible copy. | Ranges read `09:00 - 10:30`; empty values say "None". The divider glyph in the slash menu stays: it's a picture of the line it inserts. |

## Checked, no change needed

- **Server authorisation.** Every channel route checks membership; device inboxes and key-package uploads check the device is the caller's; sending a Welcome requires both sender and target to be in the channel.
- **Public pages** (`/p/…` pay links, `/f/…` forms, `/i/…` invites). Strict CSP, `nosniff`, no framing, no referrer, no `innerHTML`. The pay link only offers `https://` payment URLs. Form submissions are size-limited (64 KB) and capped per form; "I've paid" is idempotent.
- **Sign-in codes.** 5 tries per code, an address locked for a day after 20 failures, only hashes stored.
- **SQL.** Values are bound, never formatted in; the few `format!` queries splice in constants only.
- **Mail.** TLS everywhere; unencrypted connections only to this computer. Mail bodies are shown as plain text.
- **Desktop bridge.** Upload paths come only from the native file dialog or a drop, so the web view can't name arbitrary files; local file records refuse anything but UUID chunk names. Messages are plain text with no links, so nothing can navigate the web view away.
- **Motion.** Every looping animation stops under `prefers-reduced-motion`.

## Left open

- **One process-wide map for lookup limits** (`lookups`). Fine for one server process; a cluster needs it in Postgres or Redis.
- **The tour runs in the same web view as a real account.** It never writes local storage and its backend is in-page, but a shared `invoke` wrapper is the boundary. Worth a test that the tour can't reach a real op.
